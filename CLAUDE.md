# TempoStatusBarApp — Claude Guide

macOS menu bar app (Swift/SwiftUI, AppKit `NSStatusBar`) that polls the
Jira Tempo REST API hourly and shows days since the user's last worklog,
with color-coded status indicators. Targets Tempo Server/Data Center (not
Tempo Cloud). Read `docs/OVERVIEW.md` first for full architecture detail;
also `docs/api-design.md` for Tempo API work and `docs/ci-cd.md` for
workflow changes.

## Repo layout

Source files live **flat at the repo root** — no `Sources/` directory:

```
AppDelegate.swift            App entry; NSStatusBar integration
TempoService.swift           API client, data models
CredentialManager.swift      Keychain credential persistence
ContentView.swift            SwiftUI status popover
SettingsView.swift           SwiftUI settings popover
UpdateChecker.swift          GitHub Releases update check
LaunchAtLoginManager.swift   SMAppService login-item wrapper (macOS 13+)
TempoStatusBarAppTests/      XCTest unit tests (mocked)
linux/                       Linux tray app (Rust) — separate implementation
flake.nix                    Nix dev shell + package for linux/
.github/actions/             Composite actions (setup-nix)
.github/workflows/           CI/CD (PR, main, release, Linux)
TempoStatusBarApp.xcodeproj  Xcode project
```

The `linux/` crate is a **separate implementation**, not a port — it shares no
source with the Swift app and must not change it. See `docs/linux.md`.

## Conventions

- Swift API Design Guidelines; SwiftLint enforced (`.swiftlint.yml`).
- `WorklogStateManager.shared` is the single source of truth; it is
  `@MainActor` and `ObservableObject`. UI updates flow via Combine
  `@Published` properties — do not mutate state off the main actor.
- Credentials live in macOS Keychain via `CredentialManager`; service
  name is `com.stjohnsoftware.TempoStatusBarApp`. Never log or print
  `apiToken`, `githubToken`, or any credential value.
- Posting `.credentialsChanged` to `NotificationCenter` triggers an
  immediate refresh in `AppDelegate`.
- Errors use the typed `WorklogStateError` / `TempoError` /
  `CredentialError` enums. Add new cases rather than string-typed errors.
- DI for tests: `WorklogStateManager` accepts `CredentialManagerProtocol`
  and `TempoServiceProtocol`. Use `MockCredentialManager` /
  `MockTempoService` / `MockURLProtocol` patterns from the test target.
- Popover sizing: `NSPopover.contentSize` **must** match the SwiftUI
  `.frame(width:height:)` in the corresponding view (see OVERVIEW.md).
- `appVersion` is generated by a Run Script build phase into
  `DerivedData/AppVersion.swift` — never check it in.

### Linux app (`linux/`)

- Errors use `thiserror` enums mirroring the Swift `TempoError` /
  `CredentialError`. Add cases rather than string-typed errors.
- Never log or include the API token, or `token_command` **stdout**, in any
  output or error. Only a bounded stderr excerpt may surface.
- Tests are pure functions in `#[cfg(test)]` modules. Never construct a
  `TrayService` or a `keyring::Entry` and never execute a `token_command` in a
  test — CI has no D-Bus session.
- `run_tests.sh` is macOS-only; the Rust suite runs via `cargo test`.

## Building & testing

- Build: open `TempoStatusBarApp.xcodeproj` in Xcode 16+ and build (CI uses
  each self-hosted runner's newest installed Xcode via a job-scoped
  `DEVELOPER_DIR` — see the `Select Xcode` step), or
  `xcodebuild -project TempoStatusBarApp.xcodeproj -scheme TempoStatusBarApp build`.
- Tests: run `./run_tests.sh`. This is what CI uses — do not bypass it
  with plain `xcodebuild test`. The script must exit non-zero on failure.
- Minimum target: macOS 12. Gate macOS 13+ APIs (`SMAppService`) with
  `if #available(macOS 13, *)`.
- Linux app: from `linux/`, run
  `nix develop ..# --command cargo test` (likewise `cargo fmt --check`,
  `cargo clippy --all-targets -- -D warnings`). The toolchain comes from the
  repo's own `flake.nix` — never from the runner or the host.

## CI / workflows (`.github/workflows/`)

- **macOS jobs (build / test / sign) run on self-hosted runners**
  (`[self-hosted, macos, tempo]`). Linux utility jobs (Trivy, docs, cleanup, notify) run on
  `[self-hosted, linux]`.
- **Linux CI runs everything through `nix develop`** (`linux-ci.yml`, on
  `[self-hosted, linux]`). No `apt-get`, no `sudo`, no `setup-*` toolchain
  actions, no hard-coded `/nix/store/...` paths. If CI needs a tool, add it to
  `flake.nix` in the same PR.
- Rust-only changes are excluded from the macOS workflows via `paths-ignore`
  (`linux/**`, `flake.nix`, `flake.lock`), so they never occupy the shared Macs.
- **Batch related changes into PRs** — each PR runs a full macOS build+test.
  Prefer consolidating open PRs over stacking new ones. Avoid trivial
  follow-up commits that re-trigger the macOS jobs — squash/amend locally
  before pushing.
- **CI skips for docs-only changes** (see PR #112), so keep pure-docs work
  out of code PRs where practical.
- Signing certs come from repo secrets (`SIGNING_CERT_P12_BASE64`,
  `SIGNING_CERT_PASSWORD`, `KEYCHAIN_PASSWORD`). Do not change the
  signing flow without coordinating.

## Gotchas

- App runs as `LSUIElement = YES` (no Dock icon). Use `NSAlert` for the
  About dialog; `orderFrontStandardAboutPanel` does not render reliably.
- Without the explicit main menu installed in `applicationDidFinishLaunching`,
  SwiftUI `TextField`/`SecureField` lose Cmd+V/Cmd+A in popovers.
- The app is **not sandboxed**; Hardened Runtime is on with an empty
  entitlements plist for Release.
- Keychain service name is `com.stjohnsoftware.TempoStatusBarApp` — do
  not reintroduce the pre-#95 name `com.stjohnsoftware.TempoStatusBar`.

## Out of scope without explicit request

- Do not migrate to Tempo Cloud API.
- Do not add Sparkle (update-check uses GitHub Releases manually).
- Do not enable sandboxing.
